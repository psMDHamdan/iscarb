## 1. Faculty AI Copilot — Plan stage fix

### Problem
Fresh faculty lectures failed at **Plan**: Redis job ended `failed`, **0** `LectureSlidePlan` rows persisted, project status landed `failed`. Live audit (`docs/FACULTY_AUDIT_2026-08-24.md`) traced this to:

1. When the LLM timed out / returned unusable output, `generateTopicGroundedFallbackSlides` produced a 20-slide blueprint that **failed** `validatePlanStructure` (e.g. layout/function used **>2 times consecutively**).
2. Redis progress writes could throw (e.g. stop-writes-on-bgsave) and abort or obscure job progress.

### What changed
| File | Change |
|------|--------|
| `src/lib/lecture/planner/plan-generator.ts` | `setProgress()` now try/catches Redis `hset`, attempts `stop-writes-on-bgsave-error=no`, then logs and continues so plan generation is not killed by a progress write. |
| Same | Rewrote `generateTopicGroundedFallbackSlides` to emit a fixed, varied progression (hook → domain_spine → clos → … → wrap) that satisfies ≤2 consecutive function repeats, fixed S1/S3/S18–S20 roles, and interaction quotas. |
| `src/__tests__/unit/plan-generator.test.ts` | Asserts fallback output passes `validatePlanStructure(slides) === []`. |

### Verification / result
- Post-fix E2E (`docs/FACULTY_E2E_2026-08-24.md`): Plan completes with **20** `LectureSlidePlan` rows, Redis job `done`, project status **`planning`** (then approve → `approved_plan`).
- Unit test: fallback plans validate cleanly.

## 2. Density gate → warning (non-blocking)

### Problem
GATE-02 **density** (≤40 visible words / ≤5 bullets) was an **error** severity gate. Long but otherwise usable slides blocked publish. The same word-count rule was also duplicated inside `student_experience`, so density failures appeared twice as hard errors.

### What changed
| File | Change |
|------|--------|
| `src/lib/lecture/quality/types.ts` | `GATE_SEVERITY.density`: `"error"` → `"warning"`. |
| `src/lib/lecture/quality/gates/density.gate.ts` | Uses `GATE_SEVERITY.density`; findings yield `status: "warn"` (not `"fail"`). |
| `src/lib/lecture/quality/gates/student-experience.gate.ts` | Removed the duplicate `wordCount > 40` findings; density owns word count. |
| `src/app/api/iscarb/lecture/projects/[id]/validate/route.ts` | Warnings array includes gates with `severity: "warning"` and `status: "fail" \|\| "warn"`. |

### Verification / result
- Live validate after change: density appears as a **warning** (e.g. 12 findings on a long deck), **not** in publish blockers (`failedErrorGates` / density-in-blockers = false). Documented in `docs/FACULTY_VISUAL_BUGS_2026-08-24.md` § density.
- Publish continues to block only on `severity: "error"` + `status: "fail"` (and other existing rules such as unapproved slides). Faculty are expected to tighten copy when warned.

Probe script: `scripts/_verify_density_warning.mjs`.

## 3. Faculty AI Copilot — visual bug fixes

## 4. Faculty AI Copilot — per-slide image upload

### Problem
Auto-images still duplicate across slides; faculty need a first-class way to **upload / replace / revert** a slide image without storing base64 in Postgres, and without losing the choice on regenerate.

### What changed

| Area | Files / behavior |
|------|------------------|
| API | **New** `src/app/api/iscarb/lecture/projects/[id]/slides/[slideNo]/image/route.ts` — `POST` upload, `GET` serve, `DELETE` revert. Guard: faculty/admin write; GET allows student read for render. Tenant-scoped via `getScopedProject`. |
| Validation | Allowed `.jpg`/`.jpeg`/`.png`/`.webp`; max **5 MB**; clear `415` / `413` errors. |
| Storage | `src/lib/lecture/storage.ts` — `buildSlideImageStorageKey()` → `lecture/{projectId}/slide-images/{slideNo}/{file}` via existing `LECTURE_STORAGE_*` (local `.lecture-storage` in dev; S3-compatible in prod). |
| Schema fields | `src/lib/lecture/generation/types.ts` — `facultyUploadedUrl`, `facultyUploadedStorageKey`, `facultyUploadedAt`, `facultyUploadedOriginalName` on `VisualSpecification`. |
| Resolution | **New** `src/lib/lecture/visual-image.ts` — priority **`facultyUploadedUrl → fetchedImageUrl → imageUrl → fallback`**. |
| Regen safety | `generation-worker.ts` — `loadFacultyImageOverrides()` **before** early `persistArtifact` (early persist used to supersede the faculty row, then `attachVisualSpecs` re-read an empty override). Merge on early persist, attach, and final persist. |
| UI | `SlidePreviewCard.tsx` Upload/Replace/Revert; `VisualManagerModal.tsx` uploads via API (not base64); studio pages pass `projectId`. |
| Exports | `pptx-renderer.ts` prefers faculty storage key → data URI; `export-embed-images.ts` + download/export routes embed faculty images for HTML/PDF. |
| Student UX adapter | `legacy-student-ux-adapter.ts` prefers `facultyUploadedUrl`. |

### Verification / result
Evidence: `scripts/_verify_faculty_upload_out.json`, regen follow-ups, `scripts/_verify_faculty_upload_final.json` (project `cmt6or2by00o0itmgq8zwe27k`, slide 3).

| Check | Evidence |
|-------|----------|
| Upload | `200`; URL e.g. `/api/iscarb/lecture/projects/.../slides/3/image?v=…`; storage key under `lecture/.../slide-images/3/` |
| Persist | `visualSpec.facultyUploadedUrl` + `facultyUploadedStorageKey`; auto `fetchedImageUrl` kept underneath |
| Serve | GET `200`, `image/png` |
| Regen retain | After fix, version advanced (e.g. 6→8) with **same** faculty URL retained |
| Student POST | **`403`** `Forbidden: requires one of faculty, admin` |
| Bad type | **`415`** for `.gif` |
| Oversize | **`413`** for >5 MB |
| PPTX | `200`, contains PNG signature; HTML export embeds `data:image/png;base64,…` |
| Revert | DELETE clears faculty fields; slide falls back to auto Unsplash URL |
